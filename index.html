Project MUSE

Privacy Policy

Effective date 21 November 2026

This Privacy Policy explains how Project MUSE currently handles information. Project MUSE is an Electron desktop application that runs the user interface on the user's device and communicates with third-party services only when the user chooses to use a connected feature.

This policy describes the application as it is currently implemented. Pinterest account access and curated external art discovery are planned features and are not currently implemented in Project MUSE.

1. Information MUSE currently uses

Personal art library

When a user chooses Import images in Art Studio, MUSE presents a local file picker and copies the selected image files into the MUSE application data directory on the user's device. The original files are not modified or deleted.

MUSE also stores local metadata for each imported reference, including:

  • A generated reference identifier
  • The imported file name
  • The original file name
  • The title
  • The creator name
  • The chosen category
  • Source description
  • Attribution text
  • Licence text and optional licence URL
  • The import date

The metadata is stored in art-library/library.json inside the application's Electron user-data directory. Copied image files are stored in the same art-library directory. Category preferences and a limited history of recently shown reference identifiers are also stored locally.

Users can organize, update, or remove individual references in the Art Studio interface. Removing a reference deletes its copied image and its metadata entry. The original source file remains untouched.

MUSE does not scan every file on the user's device. It only receives the files that the user explicitly selects in the image picker.

Art category choices

MUSE stores the user's selected art categories locally so that random personal inspiration can follow their preferences.

General settings

MUSE stores general preference values selected by the user, including:

  • A theme preference
  • Notification preference values
  • The selected Gemini model
  • The most recent cloud-sync test timestamp

These settings may be stored in the secure configuration file described below.

Form data and temporary display data

When a user enters settings or art metadata, that information is processed locally so it can be tested, saved, or displayed. Imported preview images are read by the main process and provided to the renderer for display.

MUSE does not currently contain a general account system or server that creates a MUSE user profile.

2. Credential and integration data

Secure configuration storage

MUSE can store the following values in muse_secure_config.enc inside the Electron user-data directory:

  • Gemini API key and selected model
  • Supabase project URL and public/anonymous key
  • Theme preference
  • Notification preferences
  • The last cloud-sync test timestamp

On supported systems, MUSE uses Electron safeStorage, including operating-system-provided protection where available, to encrypt this configuration file. The source code also contains a fallback that writes configuration in plain JSON format when operating-system encryption is unavailable. The application should therefore not be described as guaranteeing encryption on every system.

This storage is local to the device and is not sent by MUSE to a MUSE server. The configuration values may be sent to the corresponding third-party service only when a user starts a connection test or another integration action.

Users can clear stored Gemini and Supabase values using the Settings interface. Users can also remove application data through their operating system or application uninstall process.

Spotify

Spotify access is optional. When the user chooses to connect:

  • MUSE opens Spotify's authorization page in the user's browser.
  • MUSE receives an authorization code through a local callback.
  • MUSE exchanges the code for a Spotify access token and optional refresh token.
  • MUSE requests the user's display name and playback information needed for the Music Studio controls.

The Spotify integration currently requests profile, playback, library, playlist, and recently played scopes. The application uses these scopes to show account status, devices, current playback, and playback controls.

Spotify access and refresh tokens are kept in the application's running memory. The source code does not currently persist these tokens in the secure configuration file or another disk-based MUSE settings file. They are cleared when the user chooses logout or when the application process ends.

Spotify user data, including display name and playback data, is processed locally for display and playback control. Spotify also receives requests needed to authenticate the account and control playback.

The user can disconnect Spotify by using the existing logout behavior. Revoking app access from the user's Spotify account settings may provide an additional account-level disconnection option.

Google Gemini

Google Gemini is optional and is configured in Settings.

When the user chooses Test Connection, MUSE sends a short test prompt to the configured Gemini model endpoint together with the supplied API key. MUSE does not currently provide a completed Gemini chat feature or send art-library content in its normal application flows.

Gemini configuration is stored locally in the secure configuration file. The API key is only sent to Google Gemini for API requests initiated by the user.

Supabase

Supabase is optional and is configured in Settings.

The current Test Connection and Sync Now implementations send the configured project URL and public/anonymous key to the configured Supabase host for a PostgREST connection test. The source currently records a local synchronization timestamp after a successful connection test.

The current implementation does not upload art-library records, Spotify playback data, Gemini prompts, or general application records to Supabase. The source does not currently implement the Realtime WebSocket data synchronization described in the settings interface. Supabase may receive connection-test requests and any future application data only if synchronization is implemented in a later version.

The Supabase public/anonymous key and project URL are stored locally when saved by the user.

Pinterest

Pinterest account access is not currently implemented. MUSE does not collect Pinterest account data, saved Pins, boards, OAuth tokens, or Pinterest profile information.

The Art Studio interface currently displays a placeholder for Pinterest. Any future implementation must clearly disclose the specific Pinterest permissions requested, how authorized content is used, how tokens are stored, and how users can disconnect Pinterest.

Wikimedia Commons and other curated sources

MUSE does not currently retrieve external art from Wikimedia Commons or another curated image source. The Discover section is also a placeholder.

Before such retrieval is implemented, MUSE should disclose the source, attribution requirements, licence information, and whether the app downloads or only links to the external reference.

3. Information sent to external servers

The following external communications occur only in the implemented features described above:

  • Spotify: account authorization, token exchange, profile information, playback state, device information, and playback commands.
  • Google Gemini: a short test prompt and API request details when the user tests the Gemini connection.
  • Supabase: a connection-test request to the user-configured Supabase URL and public/anonymous key.
  • Google Fonts: the renderer stylesheet requests a web font from Google Fonts. This may send ordinary network information such as the user's IP address and browser/request metadata to Google.

Project MUSE does not currently send the personal art library to an external MUSE server.

Pinterest and Wikimedia Commons do not receive data from MUSE for the features described in this policy until those integrations are implemented.

4. Local storage and retention

MUSE stores local information in the application's Electron user-data directory. The exact operating-system location varies by platform.

Current local items may include:

  • Copied personal art images
  • Art metadata and category preferences
  • Recent inspiration identifiers
  • Saved settings
  • Gemini configuration
  • Supabase configuration
  • Spotify connection state only while the application is running

Art and settings remain on the device until the user removes individual art references, clears the relevant settings, removes application data, or uninstalls the application. MUSE does not currently provide a single “delete all application data” control or a complete account-deletion workflow.

Spotify tokens are memory-only and end when the user logs out or closes the application. Because MUSE is a local desktop application, external services' own retention periods apply to their server-side copies and logs.

5. How to disconnect integrations and remove local content

Personal art library

Users can remove each copied reference from My Collection through the Remove action. Removing a reference deletes the copied image and associated local metadata entry. It does not affect the original image selected during import.

MUSE does not currently provide a one-click control to delete every imported image and metadata record at once.

Spotify

Users can use MUSE's Spotify logout control to clear the in-memory Spotify tokens and display name.

Gemini

Users can use the Settings clear-key control to remove the locally stored Gemini API key and saved model-related data.

Supabase

Users can use the Settings clear control to remove the locally stored Supabase URL and public/anonymous key.

Application data

Users can remove all remaining MUSE application data from the operating system's application-data directory or through an operating-system- supported uninstall process, where available.

6. Security

Project MUSE uses a limited preload-to-main-process bridge to keep some operating-system and network operations outside the renderer process. The application opens a local callback server for Spotify authorization and uses state validation and PKCE for the implemented Spotify flow.

Where supported, Electron safeStorage is used for the secure configuration file. This protection depends on the operating system and available encryption support. The source also has a plain- text fallback for configuration if hardware-level encryption is unavailable.

Art-library image files and library.json metadata are not currently encrypted by a MUSE-specific encryption mechanism. They are stored in the ordinary Electron user-data directory.

No application can guarantee absolute security. Users should protect their device account and operating-system data with appropriate access controls.

7. Children's privacy

Project MUSE is not directed at children and does not have a MUSE account registration process. Third-party integrations may have their own age requirements.

8. Changes to this policy

MUSE may add integrations or data features in later releases. When that happens, this policy should be updated before the feature is made available. Users should review the policy and integration disclosures before connecting a new service.
